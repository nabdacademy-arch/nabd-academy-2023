# تفعيل المساعد التعليمي من لوحة Supabase

بعد نجاح ملف تفعيل قاعدة البيانات، يمكن نشر خدمة المساعد من لوحة Supabase دون إعطاء رمز إدارة لأي جهة أخرى.

1. افتح **Edge Functions** في مشروع الأكاديمية، ثم اختر إنشاء/نشر دالة من المحرر (**Via Editor** إن ظهر هذا الخيار).
2. سمِّ الدالة بالضبط `nabd-tutor`؛ هذا هو الاسم الذي يستخدمه الموقع.
3. افتح [ملف الدالة المستقل](../supabase/manual/nabd-tutor.ts)، واختر **Raw**، ثم انسخ الملف كاملًا إلى `index.ts` في محرر الدالة. هذا الملف للدالة، وليس لمحرر SQL.
4. انشر الدالة مع إبقاء التحقق من JWT مفعّلًا. الدالة تتحقق كذلك من المستخدم عبر Supabase Auth قبل أي طلب للمزوّد.
5. في **Edge Function Secrets** أضف السر `OPENAI_API_KEY` بقيمة مفتاح مشروعك لدى OpenAI. لا تضع القيمة في مصدر الدالة أو GitHub أو المحادثة. مفتاح إدارة Supabase لا يصلح لهذا الحقل.
6. عنوان `SUPABASE_URL` ومفاتيح المشروع تتوفر عادةً تلقائيًا في الدوال المستضافة. تفضّل النسخة الحالية المفتاح العام من `SUPABASE_PUBLISHABLE_KEYS`، ثم تستخدم `SUPABASE_ANON_KEY` كخيار توافق للمشاريع الأقدم. يحتاج المساعد أيضًا دالة الحصة `nabd_learning_take_tutor_slot` الموجودة في ملف تفعيل قاعدة البيانات.
7. افتح مساحة التعلّم في الموقع، وسجّل الدخول بحسابك، ثم اختر **المساعد التعليمي → اسأل AI Tutor** لاختبار سؤال تأسيسي. الدالة تقبل الحسابات الموثّقة وتحد عدد الطلبات إلى ستة في الدقيقة.

النموذج الافتراضي هو `gpt-4.1-mini`؛ يمكن تغييره بسر خادم باسم `OPENAI_MODEL`. الاستخدام التوليدي يحتاج مفتاح مزوّد صالحًا وحصة متاحة لديه. البحث المرجعي في الموقع يبقى متاحًا دون مفتاح توليدي.

هذا الملف جاهز للنشر اليدوي ومختبر محليًا؛ وجوده في المستودع لا يعني أن الدالة نُشرت أو أن مفتاح المزوّد أُضيف. عند فشل الاختبار، شارك رسالة الخطأ فقط دون مفاتيح أو بيانات مرضى.

ملف الدالة المستقل مولَّد من `context.mjs` و`handler.mjs` ونقطة تشغيل Deno. الاختبار `node learning/tests/tutor-standalone.mjs` يتحقق من تطابق استجاباته مع النسخة الأصلية في حالات النجاح والمصادقة والأصل والحصة والصورة غير الصالحة وعدم التفعيل.

## تشخيص رسالة عدم التوفر

تعرض مساحة التعلّم رمز دعم وحالة HTTP بدل جمع جميع الأعطال في رسالة «غير متاح». وهي تقرأ رد الدالة القديمة أيضًا، ولا تعرض رسائل مزوّد خام أو مفاتيح أو رموز جلسات.

- `FUNCTION_NOT_FOUND`: تحقق من اسم `nabd-tutor` والمشروع الذي نُشرت فيه.
- `GATEWAY_INVALID_JWT`: بوابة Supabase رفضت رمز الجلسة قبل تشغيل الدالة. يلزم فحص توافق إعداد مصادقة الدالة مع مفاتيح التوقيع الخاصة بالمشروع؛ لا تُعطّل مصادقة الموقع أو سياسات قاعدة البيانات.
- `AUTH_INVALID`: تعذّر التحقق من المستخدم داخل الدالة.
- `CONFIG_MISSING`: أحد إعدادات الخادم المطلوبة غير متوفر.
- `QUOTA_DATABASE_UNAVAILABLE`: تعذّر فحص حصة الاستخدام في قاعدة البيانات.
- `PROVIDER_UNAVAILABLE`: الدالة القديمة وصلت إلى طلب المزوّد، لكنه فشل. حدّث الدالة إلى [الملف المستقل الحالي](../supabase/manual/nabd-tutor.ts) لتفصيل سبب فشل المزوّد.
- `PROVIDER_KEY_INVALID` أو `PROVIDER_PERMISSION_DENIED`: مفتاح المزوّد مرفوض أو لا يملك صلاحية الطلب/النموذج.
- `PROVIDER_QUOTA_EXHAUSTED`: أبلغ OpenAI عن نفاد حصة API أو حد فوترة، ويحتاج مسؤول الحساب إلى مراجعتها.
- `PROVIDER_RATE_LIMIT` أو `TUTOR_RATE_LIMIT`: حد مؤقت للطلبات؛ انتظر قبل إعادة المحاولة.
- `NETWORK_OR_CORS_ERROR`: المتصفح لم يتمكن من الوصول للدالة؛ افحص الاتصال والنطاق المسموح.

تحسين رسائل الموقع يُنشر عبر GitHub Pages. تحسين استجابات الدالة ودعم المفاتيح الجديدة يحتاجان نشر ملف الدالة المحدّث داخل Supabase؛ تحديث المستودع وحده لا يغيّر الدالة الموجودة على الخادم.
